本地已验证完整 plan 才推进、半 plan 重放、PDK offset 序列化、普通非空 Heartbeat 回调、none 和固定起点保护、停止超时资源保留。这些测试不能证明生产下游已持久化或多目标控制事件顺序。

发布前需要在实际测试环境按以下矩阵取证：

1. 普通 CDC 和全量加增量均先调用时间位点初始化，再传入 v1 envelope；直接 null/旧 Map/share CDC 的空 Map 路径不在当前支持证明内。
2. 在 plan 中途、源回调后目标未完成、目标完成但位点未保存、位点保存后分别退出进程；对比恢复位点、源事件与目标记录，允许重复而不能有缺口。
3. 普通目标、异步目标、多目标分别验证 Heartbeat 不越过尚未完成的 DML。
4. 全量阶段延长超过原 snapshot 保留窗口，固定起点租约继续有效；真实 writer 与对象存储组合下验证过期/续租竞态。
5. 重启新 attempt 后，旧进程或旧回调不能继续有效交付；记录旧 attempt 退出与资源释放证据。

每组保存实际 Engine/PDK/Paimon/目标版本、任务配置、源提交编号、目标事件、持久化 offset 和日志时间。未完成此矩阵前，不宣称 exactly-once、端到端恢复通过或可直接生产发布。
