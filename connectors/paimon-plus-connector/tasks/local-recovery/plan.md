# Paimon Plus 同机恢复实施计划

[设计依据](../../src/doc/specs/SPEC-paimon-local-recovery.md) · [可执行任务](todo.md)。范围为同一台机器、同一持久目录，允许重放，验收使用同一源位点的普通查询逐主键比较。生产仅升级连接器。项目根目录已有另一个连接器的计划，本计划使用 Paimon Plus 的功能子目录。

## 开始实施前的判断

| 从故障结果倒推的必要条件 | 怎么判断 |
| --- | --- |
| 每个应到达目标的源变更都有再交付途径，或其效果已可恢复 | 记录真实源端恢复起点、Mongo 的保存值和输入投递边界。源端从“当前”起步会越过旧变更；目标持久清单只能修复已交付的输入。 |
| 全量批次被引擎视为成功时，独立进程已能定位其全部文件 | 原生 prepare → 持久化有序消息及其有效尾 → 返回目标调用成功。清单有效尾与未知调用结果分开；允许重发同业务事件。 |
| 每个提交的输入与状态转换可唯一复认 | 在 writer 打开时固定基线、任务 owner、表世代和写入语义。封存每组 K 与有序字节摘要，首发与重试都验证目标文件及快照实际效果。 |
| 目标状态与下一次写入的索引状态都正确 | 普通批读逐键对账，并用重建索引的新 writer 再做一次更新、搬迁和删除。错误的 hash 索引可能直到后续写入才表现为重复主键。 |
| 确认和清理之后仍能识别世系分叉 | 先确认连续区间的 published，再完成 KV 对账及本机清单 GC。保留世系或可验证的最近锚点，历史过期、rollback 或外部替换且无法佐证时停机重新对账。 |

原生负对照在 [Spec 第 8 节](../../src/doc/specs/SPEC-paimon-local-recovery.md) 留有输入、结果和源码定位。P0 包括初始流位点失落、文件已删或已截断仍发布、外部 truncate/rollback、反序 hash 索引导致后继写重复键。它们分别约束来源准入、发布前校验、表级所有权和清单顺序，任一缺证都可能使最终逐键结果失真。P1 包括超时 owner、分组 K、合法或非法的空清单、有限索引 TTL、小文件和末尾内存峰值。

## 引擎故障用例

使用新建的隔离任务、源表、Mongo 进度记录、warehouse 和恢复目录。断点开关仅放在测试夹具中。以下 E(名称) 均在同版本引擎入口触发，先留下断点命中记录，再独立重启；不终止正在运行的业务同步。若连接器基线或引擎版本变化，重新归档源码提交号和相应证据。

| 名称 | 操作与可判定的结果 |
| --- | --- |
| anchor | 分别用空表、已读完的非空表，记下初始 CDC 起点 P0。全量读后制造更新/删除或新插入，在 OVER 后、首次成功 CDC 心跳前中断。比对源端实际恢复位点、Mongo 和目标行；构造将起点回退为“当前”的负对照。 |
| quiet | 两表全量，持久化 A=OVER 后中断，恢复时 A 不再有消息。另测所有表静默、A/B 混合来源分别结束、两次重启和空表。 |
| heartbeat | 跨表 A、B 仅 A 已发布时发同来源 H，然后令 B 提交失败；验证真实 Mongo 无越位。再令所有表成功但 Mongo 写入失败，检查源端 flush/保留和重放区间。分别测试串行、并发、只剩心跳、跳错、重投同一 PDK 调用。 |
| stop | 采集队列停止、在途写入、最后一次 Mongo 保存、连接器 close 和迟到 worker 的事件序；超时后不出现迟到回调、双 owner 或误清已 prepare 文件。 |
| ddl | 同表截断后插入新键，再重放旧事件；另从同一基线制造未授权 truncate、rollback 与 ID 复用。支持的路径证明世代正确，其他路径停止且保留现场。 |
| acceptance | 固定 P 并保留源端基准，逐主键比对字段、缺键、多键、已删键。归档输入负载、快照、物理文件、路由索引、Mongo、清单和两次恢复结果；故障组与无故障对照使用同一读法。 |

## 决策与交付范围

- 首版采用原生提交消息和本机小型清单。默认每次可能独立成功的 PDK 写调用都 prepare。纯 CDC 延迟 prepare 只作后续优化，要先证明引擎和源端的位点契约。
- 固定桶是第一条交付路径。HASH_DYNAMIC 和 KEY_DYNAMIC 分别取证；迟分桶、索引 TTL、删除向量、复杂合并语义按有效组合准入。已有探针与新开发的连接器端到端测试分别记录。
- 仅清单方案要求 warehouse 在整个承诺窗口保留原文件。部署须给出最老引用文件的 mtime 与年龄、可能的停机时长、可排除的并行写入及清理任务。取不到这些证据的表不开放。业务全量末尾减少快照，小文件和末尾封存内存另行实测。
- 失败时区分可重试的本地确认/KV/GC 和需要源端重新建立一致基线的永久缺文件或世系分叉。存量覆盖从已排空、源与目标对账的基线切入。旧版本回滚前先排空未决区间。
